## Resume grading rules
- Resume grading uploads the file to the Raia Resume Agent via `/external/prompts/upload-url` (pdfjs text is only a fallback); output must match `normalizeReview` in `src/lib/interview/agents.server.ts`. Each save is a `devup_resume_version` row, each grade a `devup_resume_review` linked by `version_id`; one-time XP milestones use `milestone:*` reasons on `devup_xp_event` (unique index). Why: stable ids for history and XP.
- Resume fixes ship in batches of `SUGGESTION_BATCH` (`src/lib/resume.ts`), clamped in the grader prompt, `normalizeReview` and the fallback; only `moreResumeSuggestions` issues the next batch and refuses while any current fix is unapplied. Why: no skipping
- Each user has one persistent Raia Resume Agent conversation (`devup_resume_conversation`); every grade and next-fixes request goes through it, scanned-only files via `/prompts` then recorded in the thread. Fixes are never self-marked: a new scan sends the previous review's open fixes and the grader's `integrated` ids pay XP via `awardFix`. Why: grader keeps context; goals proven by uploads
- AI token usage is estimated (chars/4) and recorded in devup_token_usage by trackUsage() in agents.server.ts, called from every Raia agent path with the acting user id; the Settings "AI usage" panel reads it via src/lib/tokens.functions.ts. Why: one estimate point, per-user visibility
